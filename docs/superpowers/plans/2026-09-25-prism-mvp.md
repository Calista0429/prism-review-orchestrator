# PRISM MVP implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development for delegated tasks and executing-plans for local integration. Track verified progress below.

**Goal:** Deliver a locally runnable, traceable PR routing demo implementing the existing design.

**Architecture:** pnpm workspaces separate pure shared contracts/risk logic from a Fastify API and React UI. PostgreSQL persists assessments, immutable policies/decisions, and append-only audit events. PGlite runs the same PostgreSQL schema for tests and a Docker-free local demo; the PostgreSQL service remains available through Compose.

**Tech Stack:** TypeScript, Zod, React, Vite, TanStack Query, Recharts, Fastify, Drizzle, PostgreSQL, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-25-prism-design.md`

## Global constraints

- The default interface language is English.
- The risk engine has no network, database, or UI dependency.
- Jev model: `typesafe/jev-1.13`; five separate score questions.
- No silent fallback from OpenRouter to demo; failures route to Needs triage.
- Policy publication and overrides append immutable records; reasons required.
- Mutation idempotency and assessment deduplication cover repeated/concurrent requests.
- No real merges, GitHub authorization, authentication, notifications, or production deployment.

  routePullRequest({ ...evidence, ci: 'failed' }, scores, policy).route,

Interfaces: API JSON is defined by shared `PullRequest`, `PullRequestDetail`, `PolicyVersion`, `SimulationResult`, `AuditEvent`, `Reviewer` types. POST mutations use `Idempotency-Key`. List responses are JSON arrays; details are complete objects.

- [ ] Write integration tests against in-memory PGlite for the five seed routes, transaction rollback, duplicate/concurrent requests, key conflicts, override reasons, immutable publication, simulation nonmutation, audit filters, provider failure, boundary validation.
- [ ] Run tests before implementing routes.
- [ ] Create relational tables with foreign keys, checks and uniqueness; apply versioned SQL migrations; seed deterministically without deleting history.
- [ ] Implement API routes from the spec plus local intake; validate all inputs and persist decisions/audit atomically.
- [ ] Implement demo scores and OpenRouter Decisions adapter, validating every score, legend and distribution. Use bounded timeout, sanitized failure, and no provider fallback.
- [ ] Verify integration and contract tests; document live testing limitation if no credentials.
